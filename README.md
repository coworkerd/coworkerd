# Coworkerd

Coworkerd is a Workers infrastructure layer for platforms, built on Cloudflare's open-source runtime
[workerd](https://github.com/cloudflare/workerd). One cluster runs all the untrusted Workers of one platform: the
platform is the administrator, its users are **tenants**, and each Worker belongs to a tenant (full name
`tenant/Worker`). Code follows the Cloudflare Workers programming model and is executed by workerd with a thin patch
series; Coworkerd adds what a shared, multi-tenant cluster needs around it:

- **isolation and limits between tenants** -- a pool of workerd processes per node with a watchdog, per-isolate CPU
  and memory limits, culprit identification and quarantine processes, each workerd started by a small launcher in a
  least-privilege environment with a system call allowlist generated by the build;
- **placement per call across nodes** -- any node is an ingress, calls (including `env.B` Service Bindings) are placed
  on a Worker's home node by rendezvous hashing, rerouted only when they certainly did not execute, and one call tree
  always sees one deployment state;
- **a declarative control plane** -- the `/v1` API of `coworkerd-apiserver` (tenants, credentials, quotas, versions,
  routes, secrets, logs, usage), with etcd as the store of desired state and S3-compatible object storage for code
  bundles, and `cowctl`, a thin command line that deploys wrangler projects.

Accounts, billing, user interfaces and stateful services (Durable Objects, KV, R2, D1 and the like) are left to the
platform on top. The components and their boundaries are described in [docs/components.md](docs/components.md).

## Status: 0.3.1

0.3.1 (2026-10-23) is the current release, for Linux `amd64` and `arm64`; it fixes the tenant-isolation and consistency gaps found while the design documents were checked against the code (0.3.0, 2026-10-18, was the first release); each architecture comes as a package (the node daemon
`coworkerd`, the control plane `coworkerd-apiserver`, the launcher `coworkerd-launcher`, the patched `workerd`,
`cowctl`) and a container image, with compose files for one or three nodes. [CHANGELOG.md](CHANGELOG.md) lists what
it contains. The `/v1` API changes only by adding fields and endpoints until 1.0.

Boundaries to know about:

- **One region.** A cluster lives in one region or an equivalent low-latency network; no routing or failover across regions.
- **Stateless Workers only.** Stateful bindings and several Cloudflare features (scheduled triggers, JS RPC, Tail
  Workers and others) are refused when a project is converted; the full list is in
  [docs/guide/compat.md](docs/guide/compat.md).
- **The sandbox needs host support.** The launcher needs unprivileged user namespaces; under Docker's default seccomp
  and AppArmor profiles it cannot set up its environment, so the default compose cluster runs without the sandbox and
  says so in its logs ([docs/guide/install.md](docs/guide/install.md), sections 3 and 4). The system call allowlist
  defaults to `observe`, and the narrower steady-state table to `off`.
- **Trust between nodes uses a shared cluster key.** Peer calls are signed with it, etcd has authentication with one
  user per node, and object storage requests are signed with a read-only identity on the nodes; mTLS and a node join
  procedure are planned for 0.4. Secret values are not encrypted at rest in etcd in this version.
- **The upstream runtime** is workerd `v1.20261012.1` with the patch series in [patches/workerd/](patches/workerd/);
  the patched workerd is the fork [coworkerd/workerd](https://github.com/coworkerd/workerd), and
  [patches/README.md](patches/README.md) describes how it follows upstream.

## Trying it

With Docker Engine 28 or newer, Docker Compose v2 and Node.js 22 or newer, a cluster, a tenant and a first deployed
Worker take about ten minutes; [docs/guide/quickstart.md](docs/guide/quickstart.md) walks through it:

```bash
tar -xzf coworkerd-0.3.1-linux-arm64.tar.gz
docker load -i coworkerd-0.3.1-linux-arm64-image.tar.gz
cd coworkerd-0.3.1-linux-arm64 && export PATH="$PWD/bin:$PATH"
(cd docker && docker compose --profile cluster up -d --wait)
```

Installation on bare metal, configuration and operations are in [docs/guide/install.md](docs/guide/install.md), and
the error codes in [docs/guide/errors.md](docs/guide/errors.md).

## Building from source

- **The daemons**: `scripts/build.sh` builds `coworkerd` and `coworkerd-apiserver` for the host with CMake and Ninja
  (it fetches Cap'n Proto and applies [patches/kj-http-abort.diff](patches/kj-http-abort.diff)); OpenSSL is required.
- **workerd**: the branch `coworkerd-v1.20261012.1` of the fork [coworkerd/workerd](https://github.com/coworkerd/workerd),
  or upstream `v1.20261012.1` checked out into `workerd/` with the series applied by
  `python3 scripts/workerd-patches.py apply`; [patches/README.md](patches/README.md) explains the series and how it
  is maintained.
- **A release**: `scripts/release.sh <version>` builds the Linux binaries in a toolchain container
  ([scripts/toolchain/](scripts/toolchain/)) and assembles the package and image; its header lists what it needs.

[CONTRIBUTING.md](CONTRIBUTING.md) has the details, and how to run a local cluster from your build.

## Repository layout

| Directory | Contents |
| --- | --- |
| `node/` | The node daemon `coworkerd`: process pool, placement, ingress and peer forwarding, membership, management endpoints |
| `apiserver/` | The control plane `coworkerd-apiserver`: `/v1`, credentials and tenants, admission and trial loads, deployment |
| `common/` | Code both daemons share: the etcd and object storage clients, the deployment state model, the Cap'n Proto schema |
| `launcher/` | `coworkerd-launcher` and its protocol |
| `cli/` | `cowctl` and its wrangler adapter |
| `runtime/` | The bridge module that runs inside workerd |
| `patches/` | The workerd patch series and the Cap'n Proto change the build applies |
| `docker/`, `examples/` | The image, compose files and example projects shipped in the release package |
| `docs/` | Design documents and the user guide ([docs/README.md](docs/README.md) lists them) |
| `scripts/` | Build, release, patch and system call allowlist tools; the Linux toolchain image (`scripts/toolchain/`) |

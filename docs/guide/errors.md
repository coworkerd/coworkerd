# Coworkerd error codes

> For release 0.3.0. The control plane's API is `/v1`, and resources have two levels: tenant -> Worker.
> Every error answer is JSON: a call's answer `{"error","reason","code",...}`, the control plane's and the management endpoints' answers `{"code","reason"}`.
> Every `reason` is cleaned: no secret values (replaced by `[redacted]`), no absolute paths (replaced by `<path>`), no stack traces, at most 400 bytes.
> The full story is in the node's log (`docker compose logs node-1`); `cowctl logs` shows what the Worker itself printed.
> From 0.3.0, `/v1` only gains fields and endpoints and never changes the meaning of an existing code; the codes below keep the meanings written here until 1.0.

## 1. When calling a Worker (the ingress's answers)

"Not executed" means the Worker's code certainly did not start, so it is safe to retry; "result uncertain" means part of it may have executed.

| HTTP | `code` | Meaning | Executed? | What to do |
| --- | --- | --- | --- | --- |
| 404 | `ROUTE_NOT_FOUND` | No route matches this host and path (routes under the default host are `/<tenant>/<Worker>`) | Not executed | See the routes with `cowctl versions` |
| 503 | `TENANT_UNAVAILABLE` | The tenant the route belongs to is being deleted; none of its Workers are served any more | Not executed | Once the deletion completes the route disappears with it (404 from then on) |
| 503 | `ROUTE_INVALID` | The matching route is invalid in the deployment state (for example written badly bypassing the control plane) | Not executed | `cowctl deploy` again |
| 503 | `WORKER_INVALID` | The Worker is invalid in the deployment state: a secret the active version declares has no value, a Binding's target is invalid, and so on; `reason` says which entry (names only) | Not executed | Supply what the reason names (for example `cowctl secret put`) or switch to another version |
| 503 | `LOAD_FAILED` | The version cannot be loaded in the load check before dispatch, `category`: `evaluation` (syntax, imports, throwing at the top level, a missing entry point, compatibility flags), `limit` (exceeding the CPU or memory limit while loading), `secret-missing` | Not executed | `evaluation`, `limit`: fix the code and deploy again; `package-unavailable`: recovers by itself once object storage is back |
| 503 | `CPU_LIMIT_EXCEEDED` | This request's CPU exceeded the limit (200 ms by the node's default, or the limit this Worker declares) and it was terminated | Partly executed | Do less computation per request |
| 503 | `MEMORY_LIMIT_EXCEEDED` | The isolate's memory exceeded the limit (128 MiB by the node's default, or the limit this Worker declares) and it was terminated | Partly executed | Use less memory |
| 503 | `RESULT_UNCERTAIN` | Failed after dispatch: the Worker threw, a stream failed halfway, the process exited, the node's drain deadline passed | Result uncertain | See `cowctl logs`; idempotent requests can be retried |
| 503 | `SECRET_UNAVAILABLE` | The deployment view of the node running it does not have this secret's value yet (it was just set) | Not executed | Retry a little later |
| 409 | `VERSION_UNAVAILABLE`, `VERSION_PIN_MISMATCH` | The deployment changed during the call, and the node it runs on does not know the version this call is locked to yet; or the node could not fetch or verify the version's code bundle before execution (another node is tried first; `ASSET_UNAVAILABLE` is the same for a static asset) | Not executed | Retry |
| 410 | `LEASE_EXPIRED` | The deadline of this call (or of its parent call) has passed | Not executed | Retry |
| 429 | `SUBREQUEST_BUDGET_EXHAUSTED` | The subrequest budget of one call tree is used up | Not executed | Make fewer Binding calls |
| 503 | `SERVER_DRAINING`, `PROCESS_UNAVAILABLE`, `QUARANTINE_UNAVAILABLE`, `PLACEMENT_EXHAUSTED`, `PEER_UNAVAILABLE`, `OVERLOADED`, `LOAD_BAND_REJECTED` | This node or all candidate nodes cannot take it for now (exiting, a process not ready, a concurrency limit, memory pressure) | Not executed | Retry, or use another ingress |
| 503 | `ASSET_UNAVAILABLE` | A static asset's bytes cannot be fetched or do not verify | Not executed | Recovers by itself once object storage is back |

The fields in the answers that refer to a node are called `nodeId`.

## 2. The control plane (`/v1` and `cowctl`)

When `cowctl` fails it prints one sentence plus the reason the control plane gave, and exits with 1. Every `/v1/` request needs `Authorization: Bearer <credential>`:
the **admin credential** (the platform's own, generated by compose's `secrets` step or given in the configuration) can do everything; a **tenant credential** (starting with `cwk_`, created by the administrator for one tenant) can act only on that tenant.

**Authentication and scope**

| HTTP | `code` | Meaning | What to do |
| --- | --- | --- | --- |
| 401 | `UNAUTHORIZED` | No credential, a malformed one, an unknown one, or one that was revoked or has expired | `COWCTL_TOKEN`, or the credential file `cowctl.json` points to (default `~/.cowctl/token`); for a revoked credential, ask the administrator for a new one |
| 403 | `FORBIDDEN` | The scope is not enough: a tenant credential accessing another tenant, or the administrator's endpoints (creating tenants, issuing credentials, `/v1/nodes`, `GET /v1/tenants`) | Use that tenant's own credential; the administrator's operations take the admin credential |

**Tenants and credentials**

| HTTP | `code` | Meaning | What to do |
| --- | --- | --- | --- |
| 404 | `TENANT_NOT_FOUND` | No such tenant | `cowctl tenant create`, or check the name |
| 404 | `CREDENTIAL_NOT_FOUND` | This tenant has no such credential (wrong `keyId`, or it belongs to another tenant) | `cowctl credential list --tenant T` |
| 409 | `CONFLICT` | The tenant already exists; the hostname to register already belongs to another tenant; the hostname to remove is still routed by this tenant's Workers; the tenant is being deleted (no more writes accepted); or concurrent writes still conflicted after 9 attempts with jittered pauses (nothing was written) | Change it as the reason says; retry on a concurrency conflict |
| 503 | `DELETION_INCOMPLETE` | Deleting the tenant stopped halfway (for example object storage was temporarily unavailable); `reason` says at which step; the tenant stays `deleting` and is not served | Once recovered, `DELETE` again; it continues from where it stopped (deletion is re-entrant) |

**Quotas and hostnames**

| HTTP | `code` | Meaning | What to do |
| --- | --- | --- | --- |
| 422 | `QUOTA_EXCEEDED` | Over the tenant's quota; `reason` starts with the quota's name: `workers`, `versionsPerWorker`, `packageBytes`, `assetFiles`, `assetBytes`, `secrets`, `hostnames`, `maxWorkerCpuMs`, `maxWorkerMemoryMiB` (a Worker-level limit above what the tenant allows), or `defaultLimits` (the tenant's default limits above its own maximum); nothing was written | Delete old versions or old Workers, or ask the administrator to adjust the quota (`cowctl tenant update T --quota name=value`) |
| 403 | `HOSTNAME_NOT_OWNED` | The route's hostname is not registered to this tenant; or the route is under the cluster's default host `*` with a path that does not start with `/<tenant>` (when the administrator turned path routing under the default host off, no route under `*` works) | Ask the administrator to register the hostname to the tenant (`cowctl tenant update T --hostname H`), or change the route |

**Deployments, versions and secrets**

| HTTP | `code` | Meaning | What to do |
| --- | --- | --- | --- |
| 422 | `LOAD_FAILED` | The new version's **trial load** failed and nothing was switched (the active version did not change); `category` in the table below | Fix the code and deploy again |
| 503 | `TRIAL_UNAVAILABLE` | No node can do the trial load (none reachable, or none registered) | `cowctl status`; retry once the cluster is ready |
| 422 | `DEPLOYMENT_REFUSED` | The checks before deployment did not pass: a declared secret has no value, the route belongs to another Worker, a Binding's target does not exist (targets are looked up only within the same tenant), the closure exceeds 64 Workers, the version to delete is the active one, and so on | Change it as the reason says; for a missing secret, `cowctl secret put` first |
| 409 | `VERSION_EXISTS` | This version id already has different content (versions are immutable); `cowctl deploy` moves on to the next id by itself, but not for one given with `--version` | Use another version id |
| 409 | `CONFLICT` | Another deployment of the same Worker runs at the same time and it still conflicted after retries; nothing was written | Retry |
| 404 | `WORKER_NOT_FOUND`, `VERSION_NOT_FOUND`, `SECRET_NOT_FOUND` | This tenant has no such Worker / the version was never uploaded / the secret is not set | Check the names |
| 422 | `SECRET_REFUSED` | The secret's name is not valid (a JavaScript identifier), the value is not UTF-8 or contains NUL, or deleting it would invalidate the active version | Change it as the reason says |
| 413 | `PACKAGE_TOO_LARGE`, `SECRET_TOO_LARGE` | The uploaded bundle exceeds the control plane's own limit (`control.maxUploadBytes`, default 160 MiB; when the tenant's quota is smaller, it reports `QUOTA_EXCEEDED`) / the secret exceeds 5 KiB | Make it smaller |

**Other**

| HTTP | `code` | Meaning | What to do |
| --- | --- | --- | --- |
| 400 | `INVALID_REQUEST` | The request is not valid (the bundle's format, the tenant's or Worker's name, JSON fields, parameters) | Use `cowctl`; names are lowercase letters, digits and `-`, at most 63 characters |
| 404 | `NOT_FOUND` | No such endpoint | -- |
| 405 | `METHOD_NOT_ALLOWED` | The endpoint exists but the method is wrong; `reason` lists the allowed methods | -- |
| 404 | `NODE_NOT_FOUND` | `/v1/nodes/{node}`: no such node (no live membership key) | `cowctl node list` |
| 503 | `ETCD_UNAVAILABLE` | The control plane cannot reach etcd; every endpoint answers this | Check the cluster (`docker compose ps`) |
| 503 | `STORAGE_UNAVAILABLE` | The control plane cannot reach object storage, or an upload failed | As above |
| 503 | `LOGS_UNAVAILABLE` | A node's log reader process did not answer (`cowctl logs` marks that node unreachable) | Retry a little later |
| 500 | `INTERNAL` | An error of the control plane itself; `reason` says what | Report it with the `reason` |

**Trial-load categories** (the `category` of `LOAD_FAILED`):

| `category` | Meaning |
| --- | --- |
| `MISSING_MODULE` | Imports a module the bundle does not have |
| `SYNTAX_ERROR` | A syntax error |
| `TOP_LEVEL_THROW` | The module throws at its top level |
| `TOP_LEVEL_AWAIT` | A top-level `await` that never completes (workerd refuses it while loading) |
| `ENTRYPOINT_MISSING` | No default export, or a default export without `fetch` |
| `COMPATIBILITY_FLAG` | Imports `node:*` without `nodejs_compat` |
| `INVALID_MODULE` | A WebAssembly or data module cannot be compiled or decoded |
| `LIMIT_EXCEEDED` | Exceeds the CPU limit (an endless loop at the top level) or the memory limit while loading (`message` says which) |
| `TIMEOUT` | Loading takes more than 5 seconds |
| `LOAD_FAILED` | Anything else (for example the process exiting while loading) |

Trial loads run in the node's **quarantine processes** (sharded by tenant, see `quarantineProcesses` in section 5 of [installing and running](install.md)),
so a new version that crashes a process does not take other tenants' in-flight requests in the ordinary processes with it.

**At conversion** (before anything is uploaded; reported locally by `cowctl deploy`): `Unsupported Wrangler configuration: <entry>` (see the [compatibility scope](compat.md)),
`Wrangler build failed: ...` (wrangler's own build errors, for example esbuild not finding an imported file), `no Wrangler configuration here`.

## 3. Management endpoints (a node's `/__coworkerd/`)

With a management token set (compose sets one by default), everything except `/__coworkerd/ready` and `/__coworkerd/probe` needs `Authorization: Bearer <token>`, otherwise 401
`UNAUTHORIZED`, and the node logs a line `[management] {"event":"unauthorized",...}` (without the token). When the control plane refuses a `/v1` request it likewise logs
`[control] {"event":"unauthorized",...}` (without the credential). The management token is used by the control plane, the operations tool and operators calling a node; nodes do not use it among themselves (their sessions are signed with the cluster key). It has nothing to do with the `/v1` credentials.

## 4. Outgoing requests of tenant code (errors `fetch` throws)

Tenant code's `fetch()` goes out through the egress service of the node it runs on ([installing and running](install.md), section 11). When the node refuses the destination or cannot connect to it, `fetch` **throws** an `Error`
(it does not return a response) whose `message` starts with the error code followed only by the rule's name or the failure's category, without any internal details (addresses, ports, names within the cluster):

```js
try { await fetch("http://10.0.0.5/"); }
catch (error) { error.message; }     // "EGRESS_DENIED: private-network"
```

| `message` | Meaning | What to do |
| --- | --- | --- |
| `EGRESS_DENIED: cluster` | The destination is one of the cluster's own addresses: a node, a peer, etcd, object storage, the control plane (`egress.clusterAddresses`), on any port | Cannot be allowed |
| `EGRESS_DENIED: loopback`, `link-local`, `metadata`, `unspecified`, `reserved` | Loopback, link-local, the clouds' metadata addresses (169.254.169.254 and others), `0.0.0.0`, reserved and multicast addresses | Cannot be allowed |
| `EGRESS_DENIED: private-network` | An internal address (RFC 1918, 100.64/10, 198.18/15, IPv6 ULA) | The platform's own internal services are allowed by the administrator per tenant (`allowInternal`) |
| `EGRESS_DENIED: port` | The default policy `public` allows only ports 80 and 443 of public addresses | The administrator writes a rule with the port into the tenant's `allow` |
| `EGRESS_DENIED: default-deny` | The cluster's default policy is `deny`, and the tenant's `allow` does not have this destination | The administrator allows it |
| `EGRESS_DENIED: tenant-deny` | The tenant's `deny` rules | -- |
| `EGRESS_DENIED: concurrency-limit`, `rate-limit` | This tenant's outgoing concurrency (default 32) or requests per second (default 100) on this node are full | Retry a little later, or ask the administrator to raise them |
| `EGRESS_DENIED: scheme`, `url` | Not `http`/`https`, or an invalid URL (for example with a user name and password) | -- |
| `EGRESS_FAILED: dns` | The node cannot resolve this name | Check the name |
| `EGRESS_FAILED: connect`, `tls`, `timeout`, `protocol` | Cannot connect, the TLS handshake or the certificate check failed, a timeout (30 seconds by default), the other side's answer is not valid HTTP | Check the destination; certificates are verified by the node against the system's root certificates |

Redirects are followed by `fetch` itself, and each hop is checked again: a public address redirecting to an internal one is refused just the same. Every request (allowed, refused, failed) has a line in the node log
`[egress] {"tenant","workerId","host","port","address","result","rule","status","requestBytes","responseBytes","durationMs",...}`,
not counted against the tenant's log quota; refusals for concurrency and rate are logged at most once per second per tenant (with the number of lines left out meanwhile), and the counts miss none.
